# Library Circulation & Finance module — decisions & gotchas log

Append-only, same format as root `docs/DECISIONS.md` (see `docs/MODULE_SPEC.md` §9.2). Entries here are scoped to this module only — a platform-wide decision is cross-referenced by its root `Dnn` id, never restated.

| LIBRARY_CIRCULATION-D1 | Fulfills root D44: one combined module (`library_circulation`) for both circulation and finance, `dependsOn: ["library_catalog"]`. Not split into two modules — the librarian's requirements treat them as one operational area (§12-14), and splitting would mean the finance tables referencing circulation's fines across a module boundary with no shared client benefit. | DECIDED |
| LIBRARY_CIRCULATION-D2 | A "student" is created by THIS module's `StudentsService.create()`, not by an admin first creating a core `User` and then linking it — the librarian's real workflow is "add a student" as one action. A random temporary password is generated server-side (never typed by the librarian) and returned ONCE in the create response with `mustChangePassword: true`; the `reader` role is assigned in the same transaction. This duplicates a small amount of core `UsersService` logic (argon2id hash, role assignment) rather than importing `UsersModule`/`UsersService` via the `apps/api/dist/...` cross-module-import pattern (root D64/D65) — a deliberate simplicity choice: no password-policy check is needed at all since the password is never operator-chosen, so there was nothing worth reusing from `assertPasswordMeetsPolicy`. | LIBRARY_CIRCULATION-D3 | `library_borrowings.status`/`library_fines.status` are `TEXT` + `CHECK`, NOT a Postgres `ENUM` — unlike `library_catalog`'s own `LIBRARY_CATALOG-D5` (which needed a real `ENUM` for its Prisma `enum` field mapping). Don't "fix" this to match `library_catalog`'s pattern without a real reason — they solve the same integrity problem two valid ways for two different reasons (that module maps to a Prisma `enum` type it exposes; this one doesn't need to). | DECIDED |
