# Library Catalog module — decisions & gotchas log

Append-only, same format as root `docs/DECISIONS.md` (see `docs/MODULE_SPEC.md` §9.2). Entries here are scoped to this module only — a platform-wide decision is cross-referenced by its root `Dnn` id, never restated.

| # | Decision | Status |
|---|---|---|
| LIBRARY_CATALOG-D1 | Directory name/manifest `key` is `library_catalog` (snake_case, not hyphenated) — the first module built, so this is where the general "directory must equal the manifest key literally" rule (root D55) was actually discovered and fixed. | DECIDED |
| LIBRARY_CATALOG-D2 | `backend.entry` points at compiled `backend/library-catalog.module.js`, both `.ts` and `.js` checked into git together (root D56) — this module is where that constraint was first hit and fixed. | DECIDED |
| LIBRARY_CATALOG-D3 | `backend/platform.ts` (root D57) originated here — every later module (`survey`, `template`) copies this file's shape as its starting point rather than re-deriving the metadata-key shim pattern from scratch. | DECIDED |
| LIBRARY_CATALOG-D4 | Borrowing/returning/fines are explicitly **not** this module's concern — the library domain splits into `library_catalog` (this one, stands alone) and a combined future `library_circulation`+`library_finance` module that will `dependsOn: ["library_catalog"]` (root D44). `library_catalog_book_copies.status` only ever reflects a copy's current state, never borrowing history — don't add history/loan fields here when that need arrives; build the dependent module instead. | DECIDED |
| LIBRARY_CATALOG-D5 | `library_catalog_book_copies.status` is a real Postgres `ENUM` (`CREATE TYPE ... AS ENUM`), not `TEXT` + `CHECK` — required for the Prisma `enum` mapping to work at all (confirmed the hard way: a plain `TEXT` column throws `type "public.x" does not exist` at the Prisma layer). Any later module needing an enum-shaped column should copy this migration's idempotent `DO $$ ... CREATE TYPE IF NOT EXISTS ...` pattern, not a bare `CREATE TYPE`. | DECIDED |
| LIBRARY_CATALOG-D6 | The public availability route (`GET /public/books/:id/availability`) is `@Audit`'ed even though it's a read — deliberate, not the usual convention (reads aren't normally audited) — specifically to exercise the platform's `actor_type='anonymous'` audit mechanic (root D34/`ARCHITECTURE.md` §8.1) with its first real, non-fixture case. Don't copy "audit every public read" as a general rule from this — it was this route's specific point, not a default. | DECIDED |
| LIBRARY_CATALOG-D7 | Deleting a book cascades (`ON DELETE CASCADE`) to its copies with no confirmation/guard at this module's own level — acceptable here because there is no borrowing history yet to lose (see D4); once `library_circulation` exists, it (not this module) is responsible for blocking a book/copy delete that has real history, per `docs/LIBRARY_MODULE_REQUIREMENTS.md` §22. If you're extending *this* module and tempted to add that guard here instead, don't — it belongs in the module that owns the history table. **Clarified (2026-09-20, see D19 below):** this describes the DB schema layer (the FK is genuinely `ON DELETE CASCADE`, no trigger/guard there). `BooksService.remove()` itself has ALWAYS had its own separate application-level guard (`ConflictException` when `book._count.copies > 0`, present since the module's original Phase 8 scaffold, `c09a92d`) that blocks deleting a book with copies at all, cascade or not — this was a pre-existing, deliberately-kept behavior (it has its own passing unit test, `books.service.spec.ts`), not something D7 was describing or that this entry overrides. D19 adds the missing way to satisfy that guard (remove a copy first) rather than removing the guard. | DECIDED |
| LIBRARY_CATALOG-D8 | **Enhancement: Combined Book + Copy Add Flow** — when creating a new book, include optional `copies` array in `CreateBookDto` to add multiple identical copies in the same request (qr_code, quantity, condition, location, acquisition_date). Implement in `BooksService.create()` as a transaction; update `BookFormDialog.tsx` to surface an optional "Add Copies" collapsible section. See `docs/LIBRARY_IMPROVEMENTS.md` §1.1. **Implemented 2026-09-20** on branch `claude/library-improvements`, commit `0d9d852` (backend already existed from `e9a491f`; this closed the frontend gap). | DECIDED |
| LIBRARY_CATALOG-D9 | **Enhancement: Book Catalog List — Copy Visibility** — add two computed columns to `BooksListPage` table: `Copies (Total)` and `Copies (Available)` showing format "2/5" (2 available out of 5 total). Requires a subquery aggregate on `library_catalog_book_copies` grouped by `book_id`. See `docs/LIBRARY_IMPROVEMENTS.md` §1.2. **Implemented** — was already live (`ea4c5bc`) as a single combined "2/5" column rather than two separate ones. | DECIDED |
| LIBRARY_CATALOG-D10 | **Enhancement: Book Copies Tab — Actions & Status** — surface the existing `/books/:bookId/copies` endpoint as a tab on `BookDetailPage` showing an interactive table with copy status (color-coded), condition, location, acquisition date, and a quick-action menu (View History, Update Status, Mark Damaged, Mark Lost). See `docs/LIBRARY_IMPROVEMENTS.md` §1.3. **Implemented 2026-09-20** on branch `claude/library-improvements`, commit `6a731e2` — kept as a single richer table with an action menu rather than promoting Copies to its own Tabs shell, since BookDetailPage has no other content that would need a sibling tab. | DECIDED |
| LIBRARY_CATALOG-D11 | **Phase A Decision (1.1): Combined Book + Copy Add** — when creating a book, `CreateBookDto` includes a nested mandatory `copy` object with fields `{qr_code, condition, location, acquisition_date}`. Both book and copy are created in one transaction. If librarian wants MORE copies, use existing `POST /books/:bookId/copies` endpoint. Nested structure reuses existing copy DTO, simpler than flat array. See `docs/LIBRARY_IMPROVEMENTS.md` §1.1. | DECIDED |
| LIBRARY_CATALOG-D12 | **Phase A Decision (2.1): Catalog History Endpoint** — `GET /api/library/copies/:copyId/catalog-history?limit=10` returns copy status/condition/location changes only (catalog domain). Circulation module provides complementary `/circulation-history` endpoint for borrowing records (see LIBRARY_CIRCULATION decisions). History stored as JSON field for flexibility. Separation respects module boundaries (root D44). | DECIDED |
| LIBRARY_CATALOG-D18 | **Feature 2.1: Return Form Information & Status (D18)** — adds `history JSONB[]` column to `library_catalog_book_copies` to track up to 100 recent changes to `status`, `condition`, `location`. Each entry records `{ timestamp: ISO8601, changes: { field: { before, after } } }`. Migration: `003_add_copy_history.sql`. **MANUAL STEP REQUIRED**: platform does not auto-apply migrations yet (root D47) — see `DOCUMENTATION.md` §"Migration Application" for the SQL + checksum registration. Once root D47 (automatic migration discovery/application) is complete, this manual step becomes unnecessary. | DECIDED — REQUIRES MANUAL MIGRATION |
| LIBRARY_CATALOG-D19 | **`DELETE /books/:bookId/copies/:id` added** — since D11 made `copy` mandatory on book creation, every book has >=1 copy by construction, and `BooksService.remove()`'s pre-existing guard (see D7's 2026-09-20 clarification) means a book could never actually be deleted through the API — there was no way to get its copy count back to zero first. Gated by the existing `books.delete` code (no new permission — matches the sub-resource pattern already used for `books.create`/`books.update` on copies). `BooksService.removeCopy()` lets the DB's genuine `ON DELETE CASCADE`-less FK from `library_borrowings.book_copy_id` (no cascade — history is never deleted, per that module's own migration comment) do the real enforcement once `library_circulation` is installed: a copy with borrowing history hits Postgres FK violation `P2003`, caught and re-thrown as a `ConflictException` (409) rather than leaking a raw 500. Found while fixing the CI e2e suite (`library-catalog.e2e-spec.ts`'s book-delete test) — full context in root `docs/DECISIONS.md`'s CI fix entry for 2026-09-20. | DECIDED |
