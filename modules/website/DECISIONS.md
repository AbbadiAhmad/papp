# Website module — decisions & gotchas log

Append-only, same format as root `docs/DECISIONS.md` (see `docs/MODULE_SPEC.md` §9.2). Entries here are scoped to this module only — a platform-wide decision is cross-referenced by its root `Dnn` id, never restated.

| # | Decision | Status |
|---|---|---|
| WEBSITE-D1 | One module, `basePath: "/site"`, covers BOTH the admin builder and the public site — not two separate modules. Admin routes are nested at `/site/admin/*` because `moduleManifestSchema`'s `superRefine` (`packages/shared-types/src/module-manifest.ts`) requires every declared route, public or authenticated, to nest under the module's single `frontend.basePath` — there is no schema carve-out for public routes to live outside it. A visitor's page literally slugged `admin` would otherwise be unreachable (React Router would always match the static `/site/admin/*` routes first); `create-page.dto.ts`'s `RESERVED_SLUGS = ['admin']` blocks that slug server-side as a defensive backstop. | DECIDED |
| WEBSITE-D2 | Block Markdown (`text`/`columns` blocks) renders through `react-markdown` directly to React elements, NOT through a backend `markdown-it` → HTML string → `sanitize-html` → `dangerouslySetInnerHTML` pipeline (the module's original plan-mode design). `react-markdown` with no `rehype-raw` plugin never executes raw HTML embedded in its Markdown input, so there is no `dangerouslySetInnerHTML` call anywhere in this module to audit — simpler and inherently safer for a React SPA than sanitizing an HTML string after the fact. `sanitize-html` (already an `apps/api` dependency used elsewhere) was deliberately NOT reused here; `markdown-it` was never installed for this module. One shared component, `frontend/pages/SafeMarkdown.tsx`, is the only call site, used by both the admin preview and the public render via `BlockRenderer.tsx`. | DECIDED |
| WEBSITE-D3 | No raw-HTML block type was added to `WEBSITE_BLOCK_TYPES` (`hero`/`text`/`image`/`columns`/`button`/`spacer` only) — this is what makes D2's "safe by construction" claim hold: there is no authoring surface anywhere in this module that accepts and renders arbitrary HTML, Markdown-wrapped or otherwise. | DECIDED |
| WEBSITE-D4 | `website_menu_items.parent_id` is in the schema but no CRUD UI or public renderer builds a nested submenu from it — same "add the column now, build the UI when a real nested-menu requirement shows up" reasoning `library_circulation`'s `LIBRARY_CIRCULATION-D9` used for its deferred `library_classes` entity. Every menu item renders as one flat row/link until then. | ASSUMED (deferred) |
| WEBSITE-D5 | `defaultRolePermissions` grants everything to `admin` only, nothing to any other base role — unlike `library_circulation` (which has an obvious `library_assistant`/`finance` split), no existing base role obviously owns "runs the public website," so nothing was granted by guesswork. A future role can be granted these permission codes explicitly through the real Permissions UI once the platform has an actual "content editor" or "marketing" role concept. | DECIDED |
| WEBSITE-D6 | `website.site_config` has no dedicated settings frontend page, same as `library_circulation.loan_policy` — root D70/D71's generic per-module settings UI still doesn't exist. Reachable today only through `GET/PUT /api/website/settings/site-config` directly; not a regression unique to this module. | ASSUMED (deferred) |
